Executive summary

Larkspur is a team-wiki SaaS (pages, comments, role-based access) built on Next.js App Router over Postgres via Prisma, with signed-cookie auth. The codebase is small and consistent. Two items matter before paying teams: a page-permission check enforced only client-side (SEC-01), and thin test coverage (QUAL-01).

Findings

highSEC-01Page-permission check runs only in the browser
Category: security · Confidence: high · Basis: documented · Effort: quick-win

Business impact: A member could reach or edit a page they shouldn't by calling the API directly. Low blast radius today, but it undermines the role system paying teams rely on.

Technical detail: The editor hides controls by role, but PATCH /api/pages/[id] does not re-check workspace role before writing.

Recommendation: Add a server-side role assertion using roles.ts before any write.

Evidence:
  • src/app/api/pages/[id]/route.ts:22-40 — writes without a server-side role check
  • src/features/pages/Editor.tsx:51-58 — role check is client-side only
